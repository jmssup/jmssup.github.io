Merkle Tree는 Tree 구조로 탐색 속도를 보장하며 저장구조로 보안성을 보장하는 자료구조이다.

 

주로 데이터를 저장하고 사용할 때 "내가 가진 데이터가 전체 데이터 집합에 올바르게 포함되어 있는가?"를 확인하는 용도로 사용된다.

 

binary Tree 구조 이며, leaf 노드는 해당 노드에 매칭 되는 데이터를 해쉬한 값을 가진다.

그리고 leaf를 제외한 노드들은 자식 노드들의 값을 더한 값을 해쉬한 값을 가진다.

 

위의 규칙을 이용하여 생성된 Tree가 Merkle Tree 이다.

 

이게 무슨 의미에서 보안성을 가지는지 얘기해보겠다.

 

 

Merkle root는 말 그대로 최상위 노드로 하위 모든 data block의 값에 대한 정보를 가지고 있다. 이 Merkle root는 데이터 탐색 및 검증시에 최종 변조 여부 검증을 위해 사용된다.

 

Merkle Proof

Merkle Tree에서 검증받으려는 데이터의 무결성을 검증하는 방법, 과정을 Merkle Proof 라고 한다.

또한 검증과정에서는 검증을 위해 검증을 받으려는 데이터와 계산하기 위한 Tree에 저장된 여러 노드들의 정보도 필요한데 이 노드 정보들의 묶음도 Merkle Proof라고 칭한다.

 

Merkle Tree에서의 data block의 무결성을 검증 방법은 다음과 같다.

1. L1 데이터를 검증하고자 함.

2. L1 데이터의 해쉬된 위치 정보(index)와 함께 root로부터 해당 위치까지 형제, 부모 노드들의 값(Merkle Proof)을 넘겨준다.

3. L1 데이터를 해싱한 값 H1 을 제공받은 이웃 노드들 H2, H34의 값과 연산하여 Merkle root까지 계산한다.

4. 최종적으로 계산한 Merkle root와 기존의 Merkle root를 비교하여 L1 데이터가 변조되었는지 확인한다.

 

만약 data block의 정보가 일부 달라진 경우 연관된 모든 노드들에 연쇄적으로 해쉬값이 변조되며 최종적으로 root의 값과 비교되어 data block에서 변조가 있었음을 알 수 있게 된다.

 

Merkle Proof 과정을 보다가 본질적인 궁금증이 생겼다.

아니 Merkle Tree에 L1 정보를 해싱한 H1이 있을텐데 왜 이 기존 H1 정보를 사용하지 않지?

이에 대해서는 3가지 정보를 더 알아야한다.

 

1. Merkle Tree는 일반적인 컴퓨터의 저장공간이 아닌 스마트폰 혹은 더 작은 저장장치가 달린 컴퓨터에서의 데이터 검증도 보장한다.

2. 저장공간이 적기에 Merkle Tree의 전체 정보는 여러 서버들(정보전달자)에 저장되어 있고 요청자는 Merkle root 정보만 가지고 있다.

3. Merkle Proof 정보를 서버들에 요청하여 받는 과정이기에 검증 요청자와 서버들 모두 신뢰할 수 없음을 가정해야한다.

 

이 3가지 상황으로 인하여 데이터의 무결성을 검증하는 과정을 신뢰할 수 있게 만들기 위해서 Merkle Proof 와 같은 과정을 거친다.

 

만약 서버에서 제공하는 정보가 H1 정보만 전달하고 검증요청자의 L1을 자체 해싱한 H1과 비교하는 과정일 경우 하나의 정보인 H1 만을 이용하여 검증 과정을 거치기에 검증요청자 측의 H1과 서버의 H1 둘다 변조된 경우 데이터의 무결성이 보장되지 않는다.

 

하지만 Merkle Proof 과정 처럼 root 정보와 이 외의 노드 정보들을 이용하여 검증 과정을 거치게 되면 데이터에 대한 검증이 더 견고해지며 이 root 정보의 변조, 다른 수많은 노드들의 변조에도 손쉽게 감지가 가능하게 된다.

 

이러한 구조는 중앙에 정보를 전체 다 저장하는 구조가 아닌 각자의 정보와 root 정보만을 가지고 데이터의 무결성을 검증하는게 가능하게 한다. (탈중앙화)

 

+ 추가로 찾은 장단점들

새로운 노드가 참여하여도 Merkle root정보만 갱신하여 전파하면 되기에 정보 갱신이 효율적이다. (장점)

만약 동일한 root 값을 가지는 서로 다른 데이터 정보가 존재하는 경우(충돌) 변조 탐지가 불가능하다. (단점)

공격자는 잠재적으로 Merkle 트리의 트랜잭션과 해당 해시를 수정할 수 있 다 보기에 51% 공격이 발생해도 무결성을 보장하지 못한다. (단점)

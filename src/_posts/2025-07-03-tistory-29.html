현대 앱, 웹 등의 인터넷 데이터들은 유출되거나 하는 피해가 항상 발생한다.

이를 위해서는 웹, 앱을 구성하는 많은 단계에 보안을 위한 처리가 이뤄져야 한다.

 

이를 위해서는 봇관리, API 보안, DoS, 지속적인 보안(DevSecOps) 등에 대한 정보가 명확해야 한다.

 

봇관리

인터넷 트래픽의 절반이상이 봇에 의한 통신으로 이뤄진다.

이중 절반은 악성 봇이며 기업의 대부분이 악성봇과 정상봇을 구분하지 못한다.

 

API 보안

현재 많은 데이터가 API를 통해 이동하는 경우가 많다.

API에서의 취약점이 따로 존재하게 되기에 이를 위한 보안을 위한 처리가 필요하다.

 

DoS

매우 오래된 공격 방식이지만 특별히 막을 수 있는 방법이 없기에 여전히 효과적인 공격 방법이다.

 

DevSecOps

신속한 개발을 위해 보안은 무시되거나 생략되는 경우가 많다. 이를 방지하기 위해 AI 기술을 사용하거나 프로세스를 정의하여 처리한다.

 

SW개발보안 프로세스 (DevSecOps)

SW개발 과정을 단계별로 나눠 보안 취약점들을 최소화 한다.

 

요구사항분석 - 설계 - 구현 - 테스트 과정으로 단계를 나눈다.

이 DevSecOps를 위해 AWS 아키텍쳐가 존재한다.

 

보안내재화 (Security by Design)

안전하게 동작되는 제품을 위해 설계단계부터 보안을 고려한다.

이를 위해 위협모델링 프로세스가 존재한다. (Threat Modeling)

 

Zero Trust

모든 사람, 과정에 대하여 신뢰할수 없다는 가정을 하고 최소한의 권한과 세밀한 통제로 취약점을 최소화 한다.

 

 

개발자의 사소한 실수로 인한 보안 취약점들

개발자가 개발을 할 때 굉장히 사소한 실수로도 보안적 취약점이 발생할 수 있다.

개발을 진행할 때 변수의 타입을 선언하고, 이에 대한 캐스팅을 할 때 취약점이 발생할 수 도 있고 사용자에게서 입력받는 과정에서 취약점이 발생할 수 도 있다. 또한 개발은 개발자가 직접 작성하는 코드 뿐만 아니라 오픈소스를 가져오는 경우도 많기에 오픈소스에 의한 취약점이 발생하는 경우도 다수 존재한다. 2023 OSSRA 보고서에 의하면 상용 소프트웨어의 코드베이스 중 76%가 오픈소스이며 이 중 48% 가 고위험군의 보안 취약점이 포함돼있다고 한다.

 

OSS 취약점 공격

대표적인 사례로는 Log4j 취약점이 있다.

2021년 11월경에 Alibaba Cloud 보안팀에 처음 발견 되었다.

Java 기반 로깅 도구인 Apache Log4j 라이브러리에 RCE 취약점이 존재했다.

 

 

공급망 해킹

취약한 소프트웨어를 사용하는 기관, 기업등에 피해를 주기 쉽다.

소프트웨어의 개발 - 설계 - 구현- 유통 의 과정에 취약점이 존재하면 공격자들은 이를 통해 광범위한 피해를 입힐 수 있다.

이를 위해 SBOM (Software Bill of Materials)가 존재한다.

소프트웨어의 빌드를 위해 사용된 여러 컴포넌트에 대한 내용과 공급망 관계를 형식에 맞춰 기록하는 방법이다.

취약점의 확산을 효과적으로 막기 쉬워지고 공급망에 대한 깊은 이해가 쉬워진다.

 

 

국내 보안 표준, 지침, 제도

클라우드 서비스(SaaS) 보안 인증이라는 보안인증제도가 존재한다.

과학기술정보통신부에서 민간 기업이 SW개발시 SW개발보안을 적용하도록 하고 있다.

행정안전부에서 행정기관등이 안전한 소프트웨어 개발을 하도록 SW개발보안 가이드를 제공하고 있다.

 

국외 보안 표준, 지침, 제도

국외에서도 다양한 표준, 지침이 존재한다.

미국에는 NIST의 안전한 소프트웨어 개발 프레임워크(SSDF) 가 존재한다. 

EU에는 NIS2(Network and Information Security Diretive 2) 지침이 존재한다.

 

OWASP(Open Web Application Security Project)에서 웹 애플리케이션 보안 강화를 위해 가장 치명적인 보안 취약점 10가지를 정리하여 주기적으로 발표한다.

이는 웹 개발자, 보안 전문가 및 조직이 보안 위협을 예방하는데 중요한 지침으로 활용된다.

API Security Risk, Mobile Risk 도 top 10을 발표하여 세부적인 분야에서의 취약점 내용도 제공하고 있다.

 

CVE 취약점 DB 활용

CVE(공통 취약점 및 노출, Common Vulnerabilities and Exporsures)는 소프트웨어 및 하드웨어의 보안 취약점을 표준화 하여 공개하는 시스템으로 보안 취약점을 표준화 하고 추적하는 중요한 시스템이다.

이를 활용하여 기업과 개발자는 보안성을 강화할 수 있다.

 

1. 취약점 발견: 보안 연구원, 기업, 기관이 새로운 보안 취약점을 발견.
2. CVE 요청: CVE Numbering Authority(CNA)에 취약점 보고.
3. CVE ID 할당: MITRE가 검토 후 CVE ID 부여.
4. 공개 및 업데이트: 취약점 세부 정보가 NVD 등에 등록되고, 보안 패치와 대응책 제공.

Architecture = Hadware/Software interface

 

컴퓨터가 어떤 프로그램을 실행하기 위해서는 기계어, 기계코드를 읽는 행위가 필요하다.

이는 CPU가 해당 기계어를 정확하게 해석해야됨을 의미한다.

 

하지만 세상에는 다양한 CPU가 존재하고 CPU 별로 가지고 있는 레지스터의 개수, 종류, 구조가 다르다.

또한 이에 맞춰 선대 개발자들이 만든 CPU가 기계어를 처리하는 방식(명령어 집합 구조)도 매우 다양하다.

 

이 글에서는 이 CPU가 기계어를 처리하는 방식에 대하여 알아보겠다.

 

명령어 집합 구조(ISA, Instruction Set Architecture)

명령어 집합 구조란?

명령어 집합 구조는 일종의 설계도라고 이해하면 된다.

CPU가 이해할 수 있는 명령어의 종류, 형식, 연산 방식, 레지스터 구조, 주소 지정 방식 등을 규정한다.

이 명령어 집합 구조가 있기에 컴파일러가 소스 코드를 읽고 ISA에 맞춰서 어셈블리와 기계어로의 변환을 수행한다.

이렇다 보니 CPU 마다 지원하는 명령어 집합이 달라서 특정 CPU 용으로 컴파일된 프로그램은 다른 CPU에서 작동하지 않는다.

이 명령어 집합 구조는 하드웨어와 직접적으로 연관돼있기에 이를 통해 하드웨어 최적화에도 연관돼있다.

 

명령어(Instruction Set)

명령어란?

CPU가 해석하고 실행할 수 있는 가장 작은 단위의 동작 지시를 의미한다.

명령어의 예시

  • 데이터 이동: MOV R1, R2 (R2의 값을 R1에 복사)
  • 산술 연산: ADD R1, R2 (R1과 R2를 더해서 R1에 저장)
  • 제어: JMP 0x0040 (특정 주소로 프로그램의 흐름을 변경)
  • 메모리 접근: LOAD R1, [ADDR] (메모리에서 값을 읽어 R1에 저장)

이렇게 각각의 명령어는 어떤 동작(opcode), 어디서/무엇을(operand), 어떻게(addressing mode)를 포함하는 형태이다.
명령어의 종류와 형식은 CPU마다 정의된 명령어 집합 구조(ISA)에 따라 달라진다.

 

명령어 집합 구조의 주요 구성 요소

명령어 포맷: 각 명령어는 여러 ‘필드’(Fields)로 분할되어 설계된다. 

  • 연산자(op-code) 필드: 어떤 연산을 수행할지 지정
  • 피연산자(operand) 필드: 데이터 또는 레지스터, 메모리 주소 등을 지정

명령어 종류는 크게 연산, 데이터 전송, 제어, 입출력 등 네 가지로 나뉜다.

  • 연산: ADD, SUB 등 산술/논리 연산
  • 데이터 전송: LOAD, STORE, MOVE 등
  • 제어: 분기(Branch), 점프(JUMP) 등
  • 입출력: I/O 명령어

주소 지정 방식(Addressing Mode): 피연산자를 어떻게 지정할 것인지(직접, 간접, 즉시 등)

레지스터 구조: 포함되는 레지스터의 개수와 역할

데이터 형식: 지원하는 데이터의 타입(정수, 실수 등)

 

그렇다면 이 명령어를 모아놓고 하드웨어와 소프트웨어의 연결을 정리해놓은 명령어 집합 구조는 어떤 방식으로 CPU에 들어가 있고 어떻게 처리하는지 알아보겠다.

1. 명령어 집합 설계 및 정의

  • CPU를 설계하는 단계에서 개발자는 CPU가 지원해야 하는 명령어(ADD, MOV, LOAD 등)와 그 인코딩 형식을 문서(ISA 명세서)로 정의한다.
  • 이 명세서에는 각 명령어의 이진수 포맷, 처리 방식(피연산자 종류, 레지스터 수 등)까지 명확하게 적혀 있다.

2. CPU 내부 회로(마이크로아키텍처) 구현

  • 하드웨어 설계자는 이 ISA를 기준으로 명령어를 해석할 수 있는 논리회로(Instruction Decoder)를 만든다.
  • 이 회로는 외부에서 전달받은 기계어 명령어(이진수 신호)를 해석해서 산술논리연산장치(ALU), 레지스터, 메모리 등 각 컴포넌트에게 신호를 보낸다.
  • 명령어의 이진 패턴이 들어오면 그에 맞는 실제 동작이 하드웨어 수준에서 자동으로 수행됩니다.

3. 컴파일러와 운영체제 역할

  • 소프트웨어(예: C, Python 코드)는 컴파일러를 통해 해당 ISA에 맞는 기계어(명령어들의 연속)로 번역된다.
  • 이 기계어 명령어들은 프로그램 실행 시 CPU에 전달되어, CPU는 자신이 "설계된 규약"에 따라 차례대로 명령어를 처리한다.

명령어 집합(ISA)은 'CPU가 이해할 수 있는 일종의 언어 사전' 이다.

CPU 내부에는 이 규약(ISA)을 해석하고 실현하는 논리회로(디코더, 연산장치 등)가 반드시 탑재된다.

개발자는 이 명령어 집합의 규칙을 시스템 설계 단계에서 미리 하드웨어에 각인시키는 것이다.

결국 프로그램 → 컴파일러 → ISA에 맞는 기계어 → CPU 내부 회로에서 실행이라는 과정으로 동작하게 됩니다.

쉽게 말해, 명령어 집합은 CPU와 개발자 모두가 반드시 지켜야 할 약속이고
이 약속이 실제 하드웨어(회로)에서 바로 동작할 수 있도록 설계와 제조 과정에서 적용된다고 볼 수 있다.

 

 

명령어 집합 구조의 종류

이 명령어 집합 구조는 대표적으로 CISC(Complex Instruction Set Computer) 와 RISC(Reduced Instruction Set Computer) 이 2가지가 존재한다.

CISC(Complex Instruction Set Computer)

x86, x86-64의 CPU에서 사용되는 명령어 집합 구조(ISA)로 인텔, AMD 등 PC 및 서버 시장을 중심으로 사용된다.

주요 특징

  • 다양한 명령어 지원
    많은 종류의 명령어와 다양한 주소 지정 방식을 지원해 하나의 명령어로 여러 연산 또는 복잡한 처리를 할 수 있다.
  • 명령어 길이 가변적
    명령어마다 길이와 포맷이 제각기 다르며 복잡한 명령어는 더 많은 비트와 사이클을 소모한다.
  • 메모리 접근의 자유로움
    산술 및 논리 연산 시에도 메모리 직접 접근이 지원된다.
  • 코드의 크기가 작아짐
    한 명령어로 복잡한 작업을 할 수 있어 프로그램 코드 길이가 줄어드는 장점이 있다.
  • 하드웨어 복잡도↑
    명령어 해석과 실행을 위해 복잡한 하드웨어(디코더, 마이크로코드 등)가 필요하다

 

RISC(Reduced Instruction Set Computer)

ARM, Apple의 M시리즈 칩, 네트워크 장비 및 가전제품에 널리 사용되는 ISA이다.

 

주요 특징

  • 뛰어난 전력 효율성: 명령어 처리 회로가 단순하여 적은 전력으로도 높은 성능을 낼 수 있습니다. 이는 배터리 수명을 늘리고 발열을 줄이는 데 결정적입니다.
  • 빠른 처리 속도와 파이프라이닝: 명령어의 길이가 고정되어 있고 대부분 1 클럭 사이클에 실행됩니다. 이는 여러 명령어를 конвейер(컨베이어 벨트)처럼 동시에 처리하는 파이프라이닝 기술의 효율을 극대화하여 실제 체감 성능을 크게 향상시킵니다.
  • 단순한 하드웨어 설계: CPU 설계가 단순해지면서 칩 개발 비용과 시간을 절감할 수 있습니다. 또한, 칩의 남는 공간에 더 큰 캐시 메모리나 그래픽 처리 장치(GPU), AI 가속기와 같은 부가 기능을 통합하기에 유리합니다.

 

 

RISC 와 CISC의 차이점 정리

RISC와 CISC의 차이는 단순히 명령어 개수의 차이를 넘어 컴퓨터를 설계하는 근본적인 철학의 차이에서 비롯된다.


구분 RISC CISC
설계 철학 복잡한 작업은 단순한 명령어 조합을 통해 **컴파일러(소프트웨어)**가 처리한다. 하나의 복잡한 명령어로 하드웨어가 직접 처리한다.
명령어 적고 단순함, 모든 명령어의 길이가 고정되어 있다. 많고 복잡함, 명령어마다 길이가 가변적이다.
메모리 접근 Load, Store 명령어로만 메모리에 접근한다. (로드-스토어 구조) 다양한 명령어가 메모리에 직접 접근하여 연산할 수 있다.
실행 속도 대부분의 명령어가 1 클럭 사이클에 실행되어 빠르고 예측이 쉽다. 명령어마다 여러 클럭 사이클이 소요되며 실행 시간을 예측하기 어렵다.
주요 예시 ARM, Apple M-Series, MIPS, RISC-V Intel x86, AMD x86-64

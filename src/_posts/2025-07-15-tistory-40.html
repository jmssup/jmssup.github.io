접근통제 개요

접근통제(Access Control) 은 적절한 권한을 가진 인가자만 특정 시스템, 정보에 접근할 수 있도록 통제하는 것을 의미한다.

 

보안 접근 통제의 목적은 어떤 목적지, 객체에 접근하려는 접근자, 주체로부터 객체의 기밀성, 무결성, 가용성을 보장하는 것이다.

 

접근 통제의 중요성은 다음과 같다.

  • 최소한의 권한만을 허용해 권한 남용을 방지한다.
  • 업무의 승인, 변경, 확인, 배포 등이 한사람에 의해 처리되지 않도록 분리할 수 있다.
  • 내부 보안 위협에 대한 예측 정확도를 높일 수 있다.
  • 안전한 보안을 위해 패스워드 관리 솔루션과 접근 제어 솔루션을 같이 도입할 수 있다.

접근 제어는 시스템의 보안 수준을 갖추기 위한 가장 기본적인 수단이다.

 

접근 통제를 위해서는 통제 절차를 구성해야 한다.

통제 절차란

  • 통제 목적을 달성하기 위해 만든 구체적인 방법, 순서, 대책이다.
  • 통제 목적이 같더라도 통제 절차는 조직 환경, 관련 기술마다 달라진다.
  • 통제가 성공하려면 통제 절차를 통제 목적에 맞춰 설계 및 운영을 해야한다.

 

접근 통제를 하는 방식들은 다음과 같다.

  1. 예방 통제 (Precnetion Control) 
  2. 적발 통제 (Detective Control)
  3. 교정 통제 (Corrective Control)
  4. 복구 통제 (Recovery Control)

예방 통제는 부적절한 사건, 상황이 일어나지 않도록 사전에 조치는 것으로 직원 채용시의 신원확인, 직무분리 등의 방법이다.

적발 통제는 부적절한 사건, 상황이 일어났을 때 시기 적절하게 식별, 보고하는 것이다. 화재 경보기, 해시 값 비교 등이 이에 해당한다.

교정 통제는 적발된 사건, 상황에 대한 피해와 손실을 막는 것이다. 귀책 사유가 있는 대상을 처벌, 재발 방지대책을 수립한다. 

복구 통제는 부적절한 사건, 상황으로 인해 발생하는 피해를 극복하는 것이다. 정상적인 운영상태로 복귀한다.

 

접근통제 모델

접근통제 모델이란 접근통제를 쉽게 적용시키기 위해 만든 개념적인 모델을 의미한다.

 

임의적 접근통제(DAC: Discretionary Access Control)

정보의 소유자가 정보의 보안 레벨의 결정하고 이에 대한 정보의 접근 통제도 수행한다.

접근하는 주체의 신분에 따라 접근 권한을 부여한다.

쉽게 권한을 변경할 수 있으나 하나의 주체마다 접근권한을 일일이 부여해줘야 한다.

임의적 접근통제는 다음의 3가지 개념으로 이뤄진다.

  • 접근가능 목록(CL: Capability List): 한 주체의 접근 가능한 객체와 권한을 명시
  • 접근통제 목록(ACL: Access Control List): 한 객체의 접근 가능한 주체와 권한 명시
  • 접근통제 메트릭스(ACM: Access Control Matrix): 접근가능 목록과 접근통제 목록을 합친 것

강제적 접근통제(MAC: Manratory Access Control)

중앙에서 정보를 수집하고 분류해 각각의 보안 레벨을 붙이고 이에 대하여 정책적으로 접근통제를 수행한다.

  • 주체 등급(Subjcet Clearance): 사용자, 주체의 보안레벨
  • 객체 등급(Object Clearance): 데이터, 객체의 보안 레벨

주체와 객체의 등급을 비교해 접근 권한을 부여하는 방식으로 객체에도 보안레벨이 부여된다.

이는 보안적으로 강력하나 시스템 성능 문제와 구현이 어렵다는 단점이 있다.

 

강제적 접근 통제 모델중에는 BLP, BIBA 가 존재한다.

BLP 모델

강제적 접근통제 모델이다.

BLP 모델은 최초의 수학적 모델로 군대의 보안 레벨과 같이 정보의 기밀성에 따라 상하 관계가 구분된 정보를 보호하기 위해 사용한다.

읽기 권한과 쓰기 권한을 부여하여 관리한다.

읽기 권한은 하위 보안 레벨의 문서를 읽는게 가능하고 쓰기 권한은 상위 보안 레벨의 문서를 쓰는게 가능하다. 각 권한은 반대의 경우는 불가능하다.

 

BIBA 모델

BLP와 반대 방식으로 수행된다.

 

+ 다른 모델들중 현대적인 모델로는 RBAC, ABAC 이라는 모델이 있다. 

 

접근통제 구현 사례

접근통제는 다양하게 구현되어 사용되고 있다.

  • DB/서버 접근통제: DB, 서버에 존재하는 다양한 데이터를 기반으로 접근통제를 수행한다.
  • SSO (Single Sign-On): 한번의 인증으로 여러 컴퓨터의 자원을 이용 가능하게 하는 인증 기능이다.
  • 키보드 보안: 실시간 암-복호화를 통해 키보드 입력의 보안을 강화하는 것이다.
  • DB 암호화: 데이터베이스에 저장된 데이터를 암호문으로 변환하는 것이다.
  • 방화벽: 네트워크 트래픽을 모니터링하여 정해진 보안 규칙으로 트래픽의 허용 또는 차단을 결정한다.
  • 네트워크 망분리: 네트워크망을 업무용, 개인용으로 분리하는 것이다.

 

웹 환경에서의 인증 방식

기본 인증

HTTP에 내장돼있는 기본 인증 방식으로 암호화 기능없이 base64로 인코딩된 사용자 ID와 암호를 클라이언트에서 바로 전송한다.

 

Digest 인증

기본 인증과 마찬가지로 HTTP 에 포함돼 있지만 암호를 MD5로 해시한다. MD5에 의한 암호 해시화에 이용되는 Nonce(서버가 생성한 무작위 문자열)를 서버와 클라이언트가 주고 받는다.

 

Session 기반 인증

세션 기반 인증은 Cookie를 사용하여 수행하는 인증 방식이다. 기본, Digest 인증 방식처럼 요청마다 사용자 ID와 암호를 송수신할 필요가 없다. 서버 측에서 세션을 생성하고 서버는 클라이언트 세션 Cookie를 전송한다.

 

Token 기반 인증 / JWT(JSON Web Token) - Restful API에서 사용한다

토큰 기반 인증은 세션 기반 인증이 사용하는 Cookie 대신 토큰을 사용한다. 토큰은 서버의 비밀 키로 서명돼 있다. 클라이언트가 서버에게 토큰과 함께 요청을 제출하면 서버는 서명이 올바른지 확인을 하고 요청에 대한 처리를 진행한다.

 

 OTP 기반 인증 (One Time Password)

TOTP는 현재 시간 또는 시간 간격을 사용해 비밀키와 조합하여 일회용 비밀번호를 생성한다.

HOTP는 카운터(와 비밀키를 조합하여 일회용 비밀번호를 생성한다. (카운터: OTP 생성시마다 값이 1씩 증가한다.)

 

OAuth, OpenID

OAuth 및 OpenID 같은 인증 프로토콜 표준은 고객에 대한 인증기능 외에도 클라이언트의 행동에 대한 권한 관리 기능도 가지고 있다. Google 이나 Facebook, Twitter 등 SNS 계정을 이용한 로그인 기능을 구현하는 것도 가능하다.

OpenID의 주요 목적은 인증(Authentication) 이고 OAuth의 주요 목적은 허가(Authorization)이다.

 

SAML(Security Assertion Markup Language 기반 인증 / SSO

SAML은 ID 제공자가 사용자를 인증하고 다음 서비스 제공자로 알려진 다른 에플리케이션에 인증 토큰을 전달할 수 있게 해주는 개방형 페더레이션의 표준이다.

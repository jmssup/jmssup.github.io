TLS는 네트워크를 통한 데이터의 전송에서 이뤄지는 암호화 기술이자 방식

 

보안에 있어서 항상 등장하며 가장 중요한 개념인 Confidentality, Integrity, Autentication 을 지키는 것이 목적이다.

 

RSA 공개 키와 개인 키 방식과 대칭 키 방식을 혼합하여 사용한다.

보안, 성능 두가지 다 충족시키기 위함이다.

주요 단계 (TLS 1.2 예시)

  1. Client Hello: 클라이언트가 서버에게 "나 이런 암호화 방식(Cipher Suite)을 쓸 수 있어"라고 인사하며 난수 값을 보냅니다.
  2. Server Hello & Certificate: 서버가 암호화 방식을 선택하고, 자신의 디지털 인증서를 클라이언트에게 보냅니다.
  3. Authentication: 클라이언트는 브라우저에 내장된 신뢰할 수 있는 기관(CA) 목록을 통해 서버의 인증서가 진짜인지 확인합니다.
  4. Key Exchange: 서로만 알 수 있는 대칭 키(Session Key)를 만들기 위해 필요한 정보를 교환합니다.
  5. Finished: 이제부터 이 대칭 키로 암호화해서 데이터를 주고받자고 약속하며 종료합니다.

 

TLS 1.3 에서는 더 간략화 된 단계를 가진다.

기존 TLS 1.2 가 서로 정보를 교환하는 두번의 루틴이 발생해야 했는데 TLS 1.3 은 한번의 정보 교환으로 처리가 가능하다.

 

주요 단계 (TLS 1.3 예시)

  1. Client Hello + Key Share: 클라이언트는 인사를 건넬 때, 서버가 선택할 만한 암호화 방식에 맞춘 자신의 키 교환 정보(Key Share)를 미리 계산해서 한꺼번에 보냅니다. (추측해서 미리 던지는 방식)
  2. Server Hello + Key Share + Finished: 서버는 클라이언트의 제안 중 하나를 선택하고, 즉시 자신의 키 정보를 담아 응답합니다. 서버는 이 시점에 이미 대칭키를 만들 수 있으므로 "준비 끝" 메시지까지 한 번에 보냅니다.
  3. Finished: 클라이언트가 서버의 응답을 확인하고 대칭키를 생성하면 끝납니다.

0-RTT (Resumption): 이전에 방문했던 사이트라면, 핸드쉐이크 과정 없이 첫 번째 요청에 바로 암호화된 데이터를 실어 보낼 수도 있습니다.

 

 

이해를 위한 간단한 표현

TLS 1.2 예시

  1. 서버의 준비 (특수 안경과 특수 봉투):
    • 서버는 세상 모든 사람에게 투명하지만 밖에서는 절대 안을 볼 수 없는 특수 봉투(공개키)를 대량으로 뿌립니다.
    • 이 봉투는 누구나 가질 수 있지만, 봉투 안을 볼 수 있는 특수 안경(개인키)은 오직 서버만 가지고 안방 깊숙이 숨겨두었습니다.
  2. 클라이언트의 비밀 생성:
    • 클라이언트는 통신에 사용할 '비밀 보라색(Pre-Master Secret)' 물감을 혼자서 은밀하게 만듭니다.
  3. 봉투에 담아 전송 (Key Exchange):
    • 클라이언트는 서버가 뿌린 특수 봉투를 하나 집어듭니다.
    • 그 안에 자신이 만든 '비밀 보라색' 물감을 넣고 입구를 꽉 봉인합니다.
    • 이 봉투를 서버에게 보냅니다. (이게 네트워크 선을 타고 지나갑니다.)
  4. 해커의 상황 (가로채기):
    • 해커는 중간에서 이 봉투를 낚아챕니다. 하지만 해커에게는 특수 안경이 없어서 봉투 안에 무슨 색 물감이 들었는지 도저히 알 수가 없습니다.
  5. 서버의 확인:
    • 서버는 배달된 봉투를 받아, 자신이 숨겨둔 특수 안경을 쓰고 안을 들여다봅니다.
    • "아하, 클라이언트가 보라색을 보냈구나!" 하고 확인합니다.
  6. 결과:
    • 이제 클라이언트와 서버 둘 다 보라색을 공유하게 되었습니다.

TLS 1.3 예시 (Diffie-Hellman 알고리즘 사용)

  1. 공개 재료 (G): 누구나 아는 '노란색' 물감이 공중에 떠 있습니다.
  2. 클라이언트의 비밀 (a): 자신만 아는 '빨간색'을 준비합니다.
  3. 서버의 비밀 (b): 자신만 아는 '파란색'을 준비합니다.
  4. Key Share 전송 (A,B):
    • 클라이언트는 노랑 + 빨강을 섞어 주황색(A)을 만들어 서버에게 줍니다.
    • 서버는 노랑 + 파랑을 섞어 연두색(B)을 만들어 클라이언트에게 줍니다.
    • 해커는 노랑, 주황, 연두를 가로챘지만, 원래의 빨강과 파랑은 모릅니다.
  5. 결합 (Shared Secret):
    • 클라이언트: 받은 연두색(노랑+파랑)에 자신의 빨간색을 섞습니다. → 갈색
    • 서버: 받은 주황색(노랑+빨강)에 자신의 파란색을 섞습니다. → 갈색

결국 양쪽 모두 [노랑 + 빨강 + 파랑]이 섞인 똑같은 갈색을 갖게 됩니다! 순서만 달랐지 포함된 성분은 같습니다.

 

실제 TLS 1.3은 지수 법칙을 활용합니다. (실제로는 더 복잡한 '타원곡선'을 쓰지만 원리는 같습니다.)

  • 약속: 클라이언트와 서버는 공개된 숫자 G와 P를 공유합니다. 
  • 클라이언트 (a,A): 비밀 숫자 a 를 정하고, A=G^a(modP) 를 계산해 보냅니다.
  • 서버 (b,B): 비밀 숫자 b 를 정하고, B=G^b(modP) 를 계산해 보냅니다.

이제 각자 받은 값을 자신의 비밀 숫자로 제곱합니다.

  • 클라이언트의 결합: B^a(modP)=(G^b)^a=G^(ba)(modP)
  • 서버의 결합: A^b(modP)=(G^a)^b=G^(ab)(modP)

양쪽의 계산 결과는 같습니다.

정보들(user, system, memory, disk, cpu, uptime)을 출력하는 구조를 제작하였다. 단순 출력문이며 sysinfo를 사용하여 함수 호출로 금방 제작 가능했다.

 

--on, --off [arguments] 구조로 on, off 기능을 구현하였다.

 

입력에 관한 파싱 은 clap crate를 이용하였다.

관련하여 config.toml 파일을 이용하여 설정을 기억하고 관리가능한 구조로 만들었다. config.toml 생성 및 저장 구조에는 serde crate와 directories crate를 사용하였다. std::fs,path::PathBuf 도 함께 사용한다.

 

개발을 진행하며 초기에는 HashSet<String>을 이용하였으나 찾아보니 활용하려는 데이터가 적은 경우 Vec<String> 자료구조를 이용하면 HashSet<String>의 생성 및 사용 비용보다도 Vec<String> 자료구조가 컴퓨터의 캐싱 구조로 인하여 더 효율이 좋다는 정보를 알게 되었다.

 

이후 Vec<String>으로 진행하다가 Enum<bool>을 이용하여 처리하는게 더 효율적이라는 정보를 알게 되어 Enum<bool> 구조를 이용하는 것으로 바꾸었다.

 

clap에는 Enum<bool>에 대하여 ValueEnum 이라는 deriver를 제공한다. 그래서 간단하게 Enum<bool> 내부의 인자에 cli로 입력받는 인자를 매칭 시키는게 가능하다.

 

Vec<String>에서 Enum으로 넘어가기 전 Vec<String>으로 개발을 하며 테스트를 진행하다 system, memory 옵션이 켜져 있음에도 처리를 못하는 경우가 있었는데 단순 문자열 입력 실수로 인해 발생한 실수 였다. 현재로는 Enum 구조로 중요 인자에 대한 문자열 타이핑 실수를 최소화 하는 구조로 진행이 가능하게 만들었다.

 

추가로 알게된 지식으로는 Rust의 컴파일러가 주소 정보를 가지고 있는 객체, 변수에 대하여 . 을 이용한 함수 호출 구조에서 만약 해당 함수를 못찾는 경우 역참조 연산을 자동으로 붙여서 추론을 진행해준다는 점이다. 이거 때문에 &str에 .contains 함수를 사용하며 "왜 이게 되지?" 라는 의문이 들었었다.

 

--on, --off에 이어 --list, --reset 옵션도 제작하였다. list는 내부에 어떤 인자가 True 즉, on 상태인지와 False, off 상태인지를 출력해주는 옵션이며 reset은 초기 default 설정으로 롤백시키는 함수이다. default 설정으로는 현재 system, memory, disk, uptime 이다.

 

--on, --off에 여러개의 인자를 동시에 입력해도 입력 가능하게 만들었다, 그리고 on과 off, reset은 상호 배타적으로 즉, on or off or reset 세 옵션 중 하나만 사용 가능하게 만들었다. 여기에 list는 함께 사용 가능하다.

 

상호배타적인 옵션을 만들기 위해서 clap의 ArgGroup을 이용하였다.

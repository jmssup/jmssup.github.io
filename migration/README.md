# 티스토리 이전 보고서

2026-10-29에 `https://myinfosub.tistory.com/sitemap.xml`에서 발견한 공개 글을 대상으로 이전했습니다. 모바일 `/m/번호` 주소를 제외한 글 139개를 모두 가져왔습니다.

## 보존한 내용

- 글 139개의 제목·작성일·본문 텍스트와 코드·이미지 위치를 보존했습니다.
- 최초 이전 시 본문 텍스트는 원본 HTML과 이전 HTML의 SHA-256이 139개 모두 동일했습니다. 이후 사용자 요청으로 128번 글의 GitHub 저장소 주소 1건을 현재 계정으로 정정했습니다. 원본 해시와 정정 내역을 함께 보존하여 그 외의 본문은 동일한지 검사합니다.
- 원래 카테고리는 `originalCategory`에 남겨 두었습니다. 새 `category`는 요청한 6개 대분류에 맞춰 지정했습니다.
- 이미지 총 50개 중 37개(약 16MB)를 저장소의 `src/assets/tistory/`에 내려받았습니다. 빌드나 글 열람 시 이 파일들은 티스토리 서버에 의존하지 않습니다.
- 이전 완료된 글 사이의 본문 링크는 GitHub Pages의 새 글 주소로 바꿨습니다. 각 글에는 티스토리 원문 링크가 있습니다.
- 광고·추적 스크립트·댓글·티스토리 관리 UI는 복사하지 않았습니다. 본문 내부 실행 코드와 이벤트 속성도 제거합니다.

원본 페이지는 수정하지 않았습니다. 제공된 프로필 PDF도 수정하지 않았고 공개 사이트에 PDF 원본을 복사하지 않았습니다.

원본 글의 코드 공백과 SVG의 줄바꿈은 그대로 보존합니다. `.gitattributes`는 가져온 글·이미지 경로에만 줄바꿈 자동 변환과 공백 경고를 적용하지 않도록 설정했습니다. 나머지 소스에는 일반 Git 공백 검사가 적용됩니다. 설정 의미는 [Git 공식 문서](https://git-scm.com/docs/gitattributes#_checking_whitespace_errors)를 참고하세요.

공개 저장소에 서명된 CDN 인증 정보가 포함되지 않도록 글의 이미지 속성과 보고서 URL에서 서명·인증 매개변수를 제거했습니다. 원본 경로와 내려받은 로컬 이미지, 본문 텍스트는 유지합니다. 이전 도구와 검증 도구에도 동일한 처리를 반영했습니다.

## 이미지 13개에 대한 한계

아래 두 글의 이미지 13개는 원본 Kakao CDN 주소가 **HTTP 404**를 반환해 내려받지 못했습니다. 원본 주소, 리퍼러를 붙인 요청, 티스토리 이미지 CDN 경로를 확인했으나 파일을 얻지 못했습니다. 본문·수식 이미지의 위치와 원본 주소는 남겼으며, 이미지에 접근할 수 없으면 화면에 안내를 표시합니다.

| 글 | 내려받지 못한 이미지 |
| --- | ---: |
| [140 — Bayes’ theorem, MLE, EM](https://myinfosub.tistory.com/140) | 6 |
| [141 — EM, ELBO](https://myinfosub.tistory.com/141) | 7 |

원본 이미지 파일이나 티스토리 백업에 해당 이미지가 있으면 `src/assets/tistory/`에 넣고 두 글의 `img src`를 교체하면 됩니다. 그림의 수식을 추측해서 새로 작성하지 않았습니다. 전체 내역과 원본 주소는 `report.json`에 있습니다.

## 검증 재실행

```sh
npm run build
npm run check
```

원본 HTML 캐시가 없어도 `report.json`의 해시와 생성된 글을 비교합니다. `npm run import:tistory` 재실행 시 이미 존재하는 글을 덮어쓰지 않으며, 실패한 이미지 기록도 유지합니다. `--refresh`를 명시한 경우에만 글을 다시 가져옵니다.
